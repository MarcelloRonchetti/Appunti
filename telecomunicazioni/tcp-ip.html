Suite TCP/IP

IP, subnetting VLSM, ARP, DHCP, TCP vs UDP, three-way handshake, strumenti diagnostici.

Reti

🧱 Lo stack TCP/IP in 4 livelli

  1. Application: protocolli di applicazione (HTTP, DNS, SMTP, FTP, SSH...). Usano TCP o UDP sotto.
  2. Transport: TCP (orientato alla connessione, affidabile) e UDP (senza connessione, veloce).
  3. Internet: IP (instradamento end-to-end via indirizzi), ICMP (controllo), ARP (risoluzione MAC).
  4. Network Access: Ethernet, Wi-Fi, PPP, ecc. Trama fisica e indirizzi MAC.

Incapsulamento: i dati partono dall'applicazione, scendono lo stack e ad ogni livello viene aggiunto un header. Sul destinatario lo stack viene risalito e gli header vengono rimossi.

Indirizzi IPv4 & subnetting

🔢 Anatomia di un indirizzo IPv4

32 bit = 4 ottetti separati da punti (es. 192.168.1.10). Diviso in Net-ID (parte rete) e Host-ID (parte host).

Subnet mask: indica quanti bit appartengono al Net-ID. Notazione CIDR /n. Es. /24 = 255.255.255.0 → primi 24 bit di rete, ultimi 8 di host.

Indirizzi speciali in ogni subnet:

  • Network address: tutti i bit host a 0 → identifica la rete (es. 192.168.1.0/24).
  • Broadcast address: tutti i bit host a 1 → invio a tutti gli host (es. 192.168.1.255/24).
  • Gli host utilizzabili sono 2n − 2 con n = bit host.

✂️ Subnetting VLSM — Variable Length Subnet Mask

Idea: partire da una rete grande e dividerla in sottoreti di dimensioni diverse in base alle esigenze reali, senza sprecare indirizzi.

Procedura:

  1. Elenca le sottoreti necessarie ordinandole per numero di host decrescente.
  2. Per ognuna calcola i bit host: n = ⌈log₂(host+2)⌉.
  3. Assegna i blocchi partendo dal più grande, allineati ai confini del blocco.

Esempio: rete 192.168.10.0/24, devo creare:

  • LAN-A: 60 host → /26 (62 host) → 192.168.10.0/26 (0–63)
  • LAN-B: 28 host → /27 (30 host) → 192.168.10.64/27 (64–95)
  • LAN-C: 12 host → /28 (14 host) → 192.168.10.96/28 (96–111)
  • Link router-router: 2 host → /30 (2 host) → 192.168.10.112/30 (112–115)

Indirizzi rimanenti (116–255) restano liberi per espansioni future. Risparmio: con subnetting classful avremmo bisogno di 4 reti /24.

Protocolli di supporto

DHCP — Dynamic Host Configuration Protocol

Assegna automaticamente IP, subnet mask, default gateway, DNS al client.

1·DISCOVER Il client invia broadcast UDP (porta 67) chiedendo un server DHCP.
2·OFFER Il server risponde offrendo un IP e i parametri.
3·REQUEST Il client richiede formalmente l'IP offerto.
4·ACK Il server conferma l'assegnazione con un lease (tempo di validità).

"DORA" = Discover, Offer, Request, Acknowledge.

ARP — Address Resolution Protocol

In una LAN i frame Ethernet usano indirizzi MAC, non IP. ARP traduce IP → MAC.

1·Cache L'host controlla la propria ARP cache per l'IP destinatario.
2·Request Se non c'è, invia ARP Request in broadcast: "chi ha IP 192.168.1.5?"
3·Reply L'host con quell'IP risponde in unicast con il suo MAC.
4·Salva Il mittente salva la coppia IP-MAC nella cache (TTL tipico ~2 min).

Comando: arp -a per visualizzare la cache.

TCP vs UDP — livello di trasporto

UDP — User Datagram Protocol

Connectionless · Best effort

Nessuna connessione, nessuna garanzia di consegna. Velocità massima, overhead minimo.

Header solo 8 byte:

16 bitSource Port
16 bitDest. Port
16 bitLength
16 bitChecksum

Usi tipici: DNS, DHCP, VoIP, streaming live, gaming online — applicazioni che preferiscono la velocità all'affidabilità.

TCP — Transmission Control Protocol

Connection-oriented · Affidabile

Connessione, garanzia di consegna in ordine, controllo di flusso e congestione tramite sliding window.

Header 20+ byte:

16 bSrc Port
16 bDst Port
32 bitSequence Number
32 bitAcknowledgment Number
8 bHLen+Flags
16 bWindow
16 bChecksum

Usi tipici: HTTP/HTTPS, SMTP, FTP, SSH — quando l'affidabilità è essenziale.

🤝 Three-way handshake (apertura connessione TCP)

  1. SYN: il client invia segmento con flag SYN=1 e Sequence Number iniziale (ISNc).
  2. SYN-ACK: il server risponde con SYN=1, ACK=1, ISNs, ACK# = ISNc+1.
  3. ACK: il client invia ACK=1, ACK# = ISNs+1. La connessione è aperta.

Dopo questo scambio entrambi i lati conoscono i numeri di sequenza dell'altro e possono cominciare a scambiare dati.

👋 Svincolo connessione (graceful close)

Avviene tipicamente con un four-way handshake: ciascun lato chiude la propria direzione indipendentemente.

  1. FIN dal lato che vuole chiudere.
  2. ACK dall'altro lato.
  3. L'altro lato eventualmente invia il proprio FIN quando ha finito.
  4. Il primo lato risponde con ACK e la connessione si chiude (TIME_WAIT per ~2·MSL).
Sliding window — controllo di flusso TCP

Il ricevitore annuncia nella Window Size dell'header quanti byte è disposto ad accettare. Il mittente non può inviare più di Window byte non confermati.

La "finestra" scorre man mano che arrivano ACK. Permette di sfruttare tutta la banda disponibile (pipeline di segmenti) senza sommergere il ricevitore.

Strumenti diagnostici

ICMP

Internet Control Message Protocol

Messaggi di errore e diagnostica del livello IP. Tipi notevoli:

  • Echo Request / Reply → ping
  • Destination Unreachable → host/rete irraggiungibile
  • Time Exceeded → TTL scaduto (base del traceroute)
  • Redirect → instradamento migliore disponibile
