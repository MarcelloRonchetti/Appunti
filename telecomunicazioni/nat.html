Network Address Translation

NAT statico, dinamico, PAT (overload), port forwarding. Connettere reti private a Internet.

Routing

🔁 Perché esiste il NAT

Gli IPv4 pubblici sono finiti (~4 miliardi, esauriti nel 2011). Le organizzazioni usano IP privati (RFC 1918) all'interno della LAN, ma per andare in Internet servono IP pubblici. Il NAT traduce IP privati ↔ IP pubblici sul router di bordo.

Terminologia:

  • Inside local: IP privato dell'host interno (es. 192.168.1.10).
  • Inside global: IP pubblico assegnato al router (es. 91.10.10.5).
  • Outside global: IP del server Internet a cui ci si connette (es. 142.250.180.4).
NAT Statico

1 IP privato ↔ 1 IP pubblico

Mapping fisso. Usato per server interni che devono essere sempre raggiungibili dallo stesso IP pubblico. Costoso (un IP pubblico per host).

ip nat inside source static 192.168.1.5 91.10.10.5
NAT Dinamico

Pool di IP pubblici

Gli host privati prendono un IP pubblico da un pool mentre serve. Quando rilasciano la connessione, l'IP torna libero. Numero host ≤ dimensione pool.

ip nat pool POOL 91.10.10.2 91.10.10.10 netmask /29 ip nat inside source list 1 pool POOL
PAT / NAT Overload

N privati ↔ 1 pubblico

Molti host privati condividono un solo IP pubblico distinguendosi per numero di porta. È quello che fa il router di casa. Migliaia di host su un IP solo.

ip nat inside source list 1 interface g0/0 overload

📥 Port forwarding — esporre un servizio interno

Problema: il NAT è asimmetrico — il traffico esce facilmente, ma uno dall'esterno non sa come raggiungere un server dentro la LAN (vede solo l'IP pubblico del router).

Soluzione: port forwarding (PAT statico). Si dice al router: "il traffico che arriva sull'IP pubblico porta X, inoltralo all'host privato Y porta Z".

! Web server interno raggiungibile da Internet ip nat inside source static tcp 192.168.1.10 80 interface g0/0 80

In ambito Mikrotik si configura come regola dst-nat nella tabella NAT.
